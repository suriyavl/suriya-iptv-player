# Secure Wallet (iOS)

A self-custody Ethereum wallet for iOS 17+, written in SwiftUI. It focuses on keeping keys safe.
You can create or import a BIP39 wallet, see your ETH balance, receive with a QR code, and send ETH
using EIP-1559 transactions on Ethereum mainnet or Sepolia.

## Build

```sh
brew install xcodegen
cd SecureWallet
xcodegen generate
open SecureWallet.xcodeproj
```

Run it on a **real device**. The simulator has no Secure Enclave, so there it falls back to a software
key, which is for UI work only. Test with **Sepolia** before you use mainnet funds.

## How keys are protected

| Layer | Mechanism |
|---|---|
| Key generation | 24-word BIP39 phrase (256-bit entropy). Generated by [Trust Wallet Core](https://github.com/trustwallet/wallet-core), which is audited and pinned to an exact version with binary checksums. No home-made cryptography. |
| Encryption at rest | The phrase is encrypted with ECIES (P-256, AES-GCM) under a **Secure Enclave** key that cannot be exported. |
| Key access policy | `.privateKeyUsage + .biometryCurrentSet`. Decrypting requires Face ID or Touch ID with the *currently enrolled* biometrics. Someone who learns your passcode cannot enroll their own face to get in. |
| Keychain item | `WhenPasscodeSetThisDeviceOnly`: never synced to iCloud, never copied to a new device from a backup, and destroyed if the device passcode is removed. |
| Each signature | Every send and every phrase reveal needs a fresh biometric check. The private key exists in memory only while one transaction is being signed, then it is zeroed. |
| App lock | The app locks after 30 s in the background. A privacy shield hides balances in the app switcher. |
| Recovery phrase display | Hidden while the screen is recorded, mirrored, or AirPlayed. You get a warning if you take a screenshot. The phrase can't be selected or copied. |
| Backup check | You can't finish creating a wallet until you re-enter 4 randomly chosen words. |
| Typing | Third-party keyboards are blocked app-wide, so a keylogger keyboard can't capture the phrase. Autocorrect is off, so the keyboard doesn't learn your words. |
| Clipboard | Addresses are copied "local only" (no Universal Clipboard) and expire after 60 s. |
| Reinstall | Keychain items survive app deletion, so a fresh install wipes any leftover vault. |
| Deleting the wallet | Requires device-owner authentication, so a thief holding an unlocked phone can't destroy it. |
| Network | HTTPS only, with no ATS exceptions. Uses an ephemeral `URLSession` (no cookies, no cache) and requires TLS 1.2 or newer. Checks `eth_chainId` against the expected chain before signing. |
| Transaction review | Checks the EIP-55 checksum (rejects mixed-case typos). Blocks sends to your own address. Shows the full address in 4-character groups, which helps against address-poisoning look-alikes. Shows the max fee and max total. Refuses to sign if the balance can't cover the amount plus the worst-case fee. The review resets whenever you edit the inputs. |
| Device integrity | Warns when the device looks jailbroken or a debugger is attached. Creating a wallet requires a device passcode and enrolled biometrics. |

## Important trade-offs

- **If you re-enroll Face ID or Touch ID, the wallet key is destroyed.** This is deliberate (see above).
  Your funds are safe, but you must restore from your paper recovery phrase. Keep it.
- Swift `String`s can't be reliably wiped from memory. WalletCore takes the phrase as a `String`, so it
  may stay in memory briefly while signing. Raw seed and key buffers (`Data`) are zeroed.
- Jailbreak detection is a heuristic. A determined attacker with root access can bypass it.
- The public RPC endpoints (publicnode.com) can see your address and IP. For more privacy, point
  `EthereumNetwork` at your own node.

## Not implemented yet

ERC-20 tokens, transaction history, ENS names, WalletConnect/dApps, multiple accounts, and an optional
BIP39 passphrase (25th word). Get a professional security audit before you hold significant funds in
this app.
